# 视觉与动效：先选对表示方式，再写状态机

当目标涉及明显的视觉质感、连续动作或用户多次反馈“不像/不动/很怪”时读取。不要把本参考强制用于无界面的软件任务。

## 1. 把形容词变成一张短视觉说明

对当前未决项写清：

- **对象**：哪一页、哪个元素；不是笼统的“网站”。
- **参考特征**：轮廓、材质、光色、比例、空间关系中真正想借鉴的部分。
- **动作**：触发、运动主体、朝向与位移、时长、接触/遮挡关系、结束状态。
- **不需要的东西**：例如长拖线、浓烟、额外装饰框；只有用户明确或实际对比确认后才作为限制。
- **验收与成本**：哪种尺寸/设备下看什么、用静帧还是连续片段、允许增加哪些资源。

不必每项都问用户。复用已确认事实，只问会改变方案的关键缺项；其他作为候选假设。不要把一张“科技风”参考图当成完整的可执行需求。

## 2. 三个独立的通过点

1. **静态外观**：对象可识别、构图/材质/配色合意。
2. **动作连续性**：开始、运动、接触/翻面/结束，以及快速反向是否合理。
3. **真实页面整合**：原控件可用、遮挡与响应式合理、路由/加载/失败行为正确。

按风险展示最小证据，不把每个像素修改都升级为审批。认可一个层级时保留其素材/布局；不能用静态认可推断动效已通过，也不能用大量功能测试替代外观验收。

## 3. 素材先满足动作要求

检查素材契约：尺寸/比例、透明通道、主体边界、前进方向、锚点/接触平面、遮挡分层、所需正面/背面/状态变体、来源许可。

在关键动作首次实现或用户质疑表现时，用一行说明**目标动作 → 实际表示方式 → 现有/缺失资源 → 可看的短片段**。例如“两张正背图配合 CSS 翻面”不等于“新增了侧翻序列”；声称资源已生成需要对应文件，声称页面已使用还需要接入证据，两者分开记录。资源清单说清角色即可，不要求每个小改动填写大表。

典型判别：
- 整张合成图不能独立驱动图中的部件；补分层资源或明确只做整体平移。
- 位移方向正确不代表物体朝向正确；旋转/压扁也不一定能表示真实背面或落地接触。
- 重复边框可能来自图片本身包含外墙与内框，不能仅凭 DOM 数量判定已修复。
- 资源缺失造成的外观问题，优先补对应资源；不要持续靠 CSS 滤镜掩盖几何或材质缺陷。

缺少中间视图不自动意味着必须生成图片或上 3D：风格化翻面可能足够。先用一个短片段核对它能否表达目标；不够时明确缺口，再比较补帧、分层、模型或接受简化的成本。候选简化方案未被认可时，不称视觉交付完成。

代码原生图形、分层图片、精灵、视频、Canvas/3D 都是有条件的选择，不默认“纯 CSS 最好”或“加引擎才高级”。先用一段短动作验证表示方式是否够用，再批量生产素材。

## 4. 状态、显隐、播放与生命周期分开

针对有反向/重复交互的效果，列一份短转换表：触发事件、进入状态、可见输出、完成条件、取消条件、清理者。一个门/面板开关至少覆盖快速反向；异步动作覆盖旧结果晚到；路由切换覆盖原组件卸载。

不要把“可见”“正在播放”“资源已准备”“功能已成功”混为一个布尔值。功能状态来自真实业务链；动画只消费必要的无敏感信息信号。部分成功或等待额外验证不是最终成功。

一次性动作依赖多项素材时，按必需/可选资源确定可绘制或解码就绪条件，在合适的阶段边界选定这一段使用的表示和版本；除非动作设计明确允许，不因资源迟到而中途混用新旧姿态。交接同时管理被替代的主体、影子、拖尾或特效，避免双影和残留。未就绪或失败时回退已有可用表达；非必需装饰不阻塞核心操作或跳转。暂停、跳过、卸载后的迟到回调也不能把已退出的效果重新带回。

对于连续粒子/音视频/Canvas：
- 明确实例由谁持有，何时创建、暂停和销毁；不因每次显隐就无意叠加实例。
- 重开是否接续、重置还是重新发射，要由目标动作决定，不能把某次项目的接续策略规定为全部动画的答案。
- 需要接续时复用实例/时间；关闭后延迟暂停的任务应可取消，避免新一轮被旧定时器停止。
- 看不见不等于停止计算。检查暂停、后台、离屏、卸载和资源失败；提供合适的静态降级。
- 重复轮数和预算按风险选择，测节点/监听器/定时器/请求/帧数，不把某项目的固定粒子数量或帧率搬到所有产品。

## 5. 验证用户真正看见的东西

- 循环动画至少比较不同时刻的实际画面/像素/几何变化；`animation: running`、RAF 计数、成功日志只是辅助证据。
- 瞬时效果用浏览器内有界时间线采样或连续录屏；不要用截图调用耗时推断某帧一定存在。
- 同时检查冷加载、慢/坏资源、桌面/手机、系统减少动态及手动暂停的有效行为。**先走用户实际默认路径，不靠调试开关或特别链接才能通过。** 再看差异分支；若默认降级隐藏了约定结果，应把它作为需求与策略的冲突，而不是“分支按代码执行”就验收通过。
- 将必需反馈、一次性效果、持续背景开销和用户手动退出分开考虑。性能降级或系统偏好可能需要替代表达；选择与用户目标冲突时明确取舍，不静默关闭目标效果，也不一律覆盖系统偏好。新增操作入口只有符合已确认的使用约定才算完成，不能靠强迫用户点新按钮结束问题。
- 性能报告分清构建、服务端、网络、浏览器主线程、GPU/进程内存；不能从 JS 堆单项推导整机轻量。
- 测试与发布用同一份可识别产物。用户看到旧效果时先核对实际资源和入口，不能仅让其反复刷新。
