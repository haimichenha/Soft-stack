# 隔离 React 动效练习

适用于用户要理解动态效果、但当前真实应用会在加载或提交时联系后端的情况。先定向读取项目入口、路由、相关组件和样式，确认哪些网络请求会自动发生；目录名或页面看起来像演示，不能证明它离线。

将练习放在独立入口或隔离项目中，复用已安装的兼容依赖，不导入真实认证页面、用户状态容器或 API 封装。演示按钮必须标明模拟，不保存或输出生产凭据。测试时阻断外部请求，确认只加载本地静态资源。

教学顺序：

1. 先展示一个真实 UI 行为从事件到 `useState` 再到渲染的链路。
2. 用一个本地状态控制两三个静态姿势；解释 props 与 JSX 的对应关系。
3. 添加 CSS transition/keyframes；说明 CSS 负责帧间视觉变化，React 只决定进入哪个阶段。
4. 只有一次性动画需要定时或外部订阅时才引入 Effect，展示清理并验证快速切换与卸载；不要教成“动画都用 Effect”。
5. 再讲真实数据/认证和视觉状态如何分离，不在练习里连接后端。

验收分别记录：构建结果、浏览器观察、请求拦截结果、减少动态、手机布局和用户对概念的实际理解。构建不证明浏览器交互；离线练习通过不证明真实集成；用户答不上来也不阻塞继续实践。

涉及有辨识度的角色或视觉题材时，若用户认为“技术可用但不像目标”，将视觉结果单独记为未通过；先核对参考图属于哪个对象、轮廓/材质/动作是否可识别，以及素材来源和授权，再决定是自绘分层矢量、生成概念图还是引入已授权图像。不要仅因 build/test 通过就持续往错误角色上叠滤镜。

用户提供完整界面/动画帧参考时，先分辨可迁移的布局层、遮挡关系、状态变化与主要操作，再决定原创页面怎么组合；把来源画面作为观察材料，不直接放进产品或照搬特定纹样、角色、文案。静态生成的 UI 概念图可帮助确认气质，但其文字和按钮未必对应真实功能，接入前必须回到现有组件与接口核对。

把具体项目的端口、路径、设计文案和设备型号留在项目文档，不写进此通用参考。只有用户要求时才将隔离原型接入真实应用，并以实际成功/失败/等待路径做回归。

## 避免练习长期变成无法迁移的平行产品

上面的独立入口用于概念学习和视觉探索。目标转为改造已有产品后，应切换到“原组件/路由 + 可关闭的新展示层 + 受控依赖”的集成实验，而不是一直扩展假表单和假导航。

此时可以加载真实前端组件，但在隔离的本地测试环境替换网络响应并阻断越界请求；不读取生产会话，不填真实凭据，不将测试服务部署到公网。先迁入一个很小但贯通的真实交互，验证布局、事件、状态和卸载边界，再继续扩展效果。

首次效果原型通过不代表该集成已完成。交付状态与发布读回见 [软件交付检查](delivery-checks.md)，动作和素材问题见 [视觉与动效验收](visual-motion-acceptance.md)。
