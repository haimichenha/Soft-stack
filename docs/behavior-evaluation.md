# SS 行为回放与维护

`tests/test_server.py`、`test_registration.py` 检查 MCP/安装行为；`test_skill_package.py` 检查技能链接和案例完整性。它们**不证明模型会正确完成软件任务**。

`tests/behavior/cases/` 提供四个脱敏、跨场景的原始请求：默认环境差异、素材能力缺口、执行器失败、CLI 默认契约。`tests/behavior/rubric.json` 是评审标准，不是自动关键词评分器。

## 怎样回放

1. 只选本次修改最相关的案例。给评估者当前 `skills/software-stack/SKILL.md` 和对应 `request.md`；允许按需读技能参考。不要同时提供 rubric、预设根因或上一轮结论。
2. 默认只读、无网络、无模型网关/部署/真实账号操作。这里的响应回放验证下一步决策与报告，不冒充实际端到端开发；需要真实实现时另选隔离项目和授权范围。
3. 评审者随后逐条对照 rubric，看实际决定、拟议操作和证据边界；引用具体输出。不以出现“默认”“素材”等词就判通过，也不把不同标准下的结果拼成通过率。
4. 记录输入/技能指纹、评估者、是否真正执行操作、通过/失败项和未覆盖范围。运行记录放在忽略的 `.local/`；案例本身可随包维护。只做人工走查时注明非独立评估。

没有明确授权不为回放调用付费外部模型。修订触发路径、引入复杂流程或反复出现同类失败时，可按授权进行一次小规模独立回放；普通文字改动不强制全量模型评估。

## 包验证

仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
```

再使用当前环境 `skill-creator` 提供的 `quick_validate.py` 检查技能格式。通过格式/包测试、通过少量回放、跨项目长期减少返工，是三个不同结论。

## 更新边界

先在源包修订并审阅差异，再更新已安装副本；记录更新前后哈希并保留仅技能文本的备份。安装副本若出现源基线之外的编辑应停止核对，不覆盖。`register_local.py` 保持只新增/冲突停止，不用放宽注册器来更新文档；无需重写客户端配置、扩大 MCP 权限或修改 AS。已有会话是否重新读取指令需要单独核实，不等同于文件同步。
